01

Classes & Objects

The blueprint and the things built from it
Class

A blueprint. It describes what data something has and what it can do.

Object

One real thing built from the blueprint. You can make as many as you like.

basics.py
class Dog:
    species = "Canine"              # class attribute: shared by all dogs

    def __init__(self, name, age):  # runs when an object is created
        self.name = name            # instance attributes: one per object
        self.age = age

    def bark(self):
        return f"{self.name} says Woof!"

    def __str__(self):              # what print() shows
        return f"{self.name} ({self.age})"

d1 = Dog("Tommy", 3)
d2 = Dog("Bruno", 5)
print(d1.bark())
print(d2)
Tommy says Woof!
Bruno (5)
What is self?

self is the object the method is being called on. When you write d1.bark(), Python quietly passes d1 as self. It is only a naming habit, but always follow it.

02

Method Types

Instance, class and static methods
TypeFirst argumentUse it when
InstanceselfYou need one object's data. The default kind.
ClassclsYou need class-level data, or an alternative constructor.
StaticnoneA helper that fits the class topic but needs no object or class data.
methods.py
class Student:
    school = "ABC School"

    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def result(self):                   # instance method
        return "Pass" if self.marks >= 40 else "Fail"

    @classmethod
    def from_string(cls, text):         # alternative constructor
        name, marks = text.split("-")
        return cls(name, int(marks))

    @staticmethod
    def is_valid(marks):                # no self, no cls
        return 0 <= marks <= 100

s = Student.from_string("Aman-72")
print(s.name, s.result())
print(Student.is_valid(120))
Aman Pass
False
03

Encapsulation

Pillar 1 · Keep data safe inside the object

Bundle data and the methods that use it together, and control who can touch the data. Python uses naming conventions instead of strict locks.

StyleMeaning
namePublic. Anyone can use it.
_nameProtected by convention. "Please don't touch from outside."
__namePrivate. Python renames it internally to make accidental access hard.
encapsulation.py
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance        # private

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def get_balance(self):
        return self.__balance

acc = BankAccount(1000)
acc.deposit(500)
print(acc.get_balance())
print(acc.__balance)                    # error: no direct access
1500
AttributeError: 'BankAccount' object has no attribute '__balance'
04

Inheritance

Pillar 2 · Reuse code from a parent class

A child class gets everything the parent has and can add or change things. Use super() to call the parent's version.

inheritance.py
class Animal:
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(f"{self.name} is eating")

class Dog(Animal):                      # Dog inherits from Animal
    def __init__(self, name, breed):
        super().__init__(name)          # reuse the parent's setup
        self.breed = breed

    def bark(self):
        print("Woof!")

d = Dog("Tommy", "Labrador")
d.eat()                                 # inherited
d.bark()                                # its own
Tommy is eating
Woof!
Single

class B(A) has one parent.

Multiple

class C(A, B) has two parents. Python checks A first, then B.

Tip

Ask "is a?" before inheriting. A Dog is an Animal, so inheritance fits. A Car is not an Engine, it has an Engine, so keep an engine object inside Car instead.

05

Polymorphism

Pillar 3 · Same method name, different behavior

Many shapes, one interface. You call the same method on different objects and each responds in its own way. Overriding a parent method is the most common form.

polymorphism.py
class Cat:
    def speak(self):
        return "Meow"

class Dog:
    def speak(self):
        return "Woof"

class Cow:
    def speak(self):
        return "Moo"

for animal in [Cat(), Dog(), Cow()]:
    print(animal.speak())               # same call, different result
Meow
Woof
Moo
Duck typing

Python doesn't care about the class, only that the object has the method you call. "If it quacks like a duck, it's a duck." That is why the loop above works even though the three classes share no parent.

06

Abstraction

Pillar 4 · Show what it does, hide how

You press the car's accelerator without knowing how the engine works. In Python, an abstract class defines the methods every child must provide, without writing them. Use the abc module.

abstraction.py
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass                            # children must fill this in

class Circle(Shape):
    def __init__(self, r):
        self.r = r

    def area(self):
        return 3.14 * self.r ** 2

print(Circle(5).area())
s = Shape()                             # error: can't build an abstract class
78.5
TypeError: Can't instantiate abstract class Shape
Don't mix up

Encapsulation hides data so it can't be misused. Abstraction hides complexity so using the class is easy.

07

Decorators

Built-in ones you will use in classes

A decorator is a line starting with @ placed above a function. It wraps the function to add behavior. You already saw @classmethod, @staticmethod and @abstractmethod. The most useful one for beginners is @property.

@property: a method that acts like an attribute

property.py
class Person:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):                      # read: p.age
        return self._age

    @age.setter
    def age(self, value):               # write: p.age = 30
        if value < 0:
            raise ValueError("Age can't be negative")
        self._age = value

p = Person(20)
p.age = 25                              # runs the setter
print(p.age)
p.age = -5                              # error
25
ValueError: Age can't be negative

Writing your own decorator

my_decorator.py
def log(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@log                                    # same as: greet = log(greet)
def greet(name):
    print(f"Hello {name}")

greet("Riya")
Calling greet
Hello Riya
